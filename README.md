# FlashCards

Личные учебные карточки для студентов медицинского колледжа. Текущая доработка реализована в отдельной ветке и проходит приёмку; рабочий сайт пока использует предыдущую версию. [Результаты проверки](docs/test-results.md).

## Возможности новой версии

- Три предмета: анатомия, латынь, микробиология; внутри — личные темы и наборы.
- Занятия по всем предметам, одному предмету или одной теме: все карточки либо наступившие повторения.
- Личные карточки и прогресс; ручное добавление, корзина и восстановление.
- Библиотека явно опубликованных версий. Взятая копия сохраняет исходного автора, редактируется независимо и не переносит чужой прогресс.
- Собственная Google-таблица для каждого предмета; массовое добавление, двустороннее обновление, показ спорных правок. Для работы нужны настройки Google OAuth.
- Регистрация по обычной ссылке, вход по имени или email и восстановление пароля.

## Технологии

- Python 3 + Flask (сервер)
- HTML/CSS/JS (одностраничный фронтенд, без сборки)
- PostgreSQL на хостинге; JSON-файлы для однопроцессной локальной разработки

## Запуск локально

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

Приложение откроется на `http://localhost:8081`.

## Запуск на хостинге (Gunicorn)

```bash
pip install -r requirements.txt
gunicorn app:app --bind 0.0.0.0:8081
```

Порт можно задать через переменную окружения `PORT`.

## Публикация на Vercel

1. Импортируйте этот репозиторий в Vercel, выбрав фреймворк **Flask** и корень репозитория.
2. Подключите PostgreSQL (например, Neon через раздел Storage) и задайте `DATABASE_URL` со строкой подключения. Также поддерживается `POSTGRES_URL`.
3. При необходимости задайте отдельный `SECRET_KEY` — случайную постоянную строку, минимум 32 случайных байта. По умолчанию ключ сессий автоматически выводится через HMAC-SHA256 из секретной строки подключения с отдельной меткой приложения. При смене строки подключения пользователям потребуется войти заново. Не добавляйте секреты в Git.
4. Запустите Deploy. Таблица `flashcards_documents` создаётся автоматически при первом обращении к API.
5. Проверьте регистрацию, вход, оценку карточки и сохранение прогресса после выхода и повторного входа.

На Vercel аккаунты, личные карточки и прогресс хранятся в PostgreSQL. Локальный запуск без `DATABASE_URL` по-прежнему использует JSON-файлы. Для многопроцессного запуска также используйте PostgreSQL. На Vercel приложение отказывается записывать данные, пока база не подключена.

Вход подтверждается подписанной cookie сессии; одного имени в адресе запроса недостаточно. Локально без `SECRET_KEY` сессия сбрасывается при перезапуске сервера.

`cards.json` используется при переносе старых профилей. Существующим пользователям сохраняются прежние карточки и прогресс; новый профиль начинается с пустых личных наборов. Данные прежнего локального приложения не появляются на хостинге автоматически: приватный `users.json` нельзя добавлять в Git.

## Настройка отправки писем (восстановление пароля)

Отправка автоматически включается после настройки одного из вариантов в Vercel → Settings → Environment Variables (Production), затем нужен Redeploy:

- Resend: `RESEND_API_KEY` и `MAIL_FROM` (адрес на подтверждённом домене).
- SMTP: `MAIL_FROM`, `SMTP_HOST`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_PORT` (465 для TLS, 587 для STARTTLS). Для Gmail: `smtp.gmail.com`, порт 465, адрес Gmail и отдельный пароль приложения. Обычный пароль аккаунта Google не подходит.

Секреты добавляйте только в настройки хостинга. Не передавайте их в чате и не сохраняйте в Git. Внешние почтовые скрипты на компьютере больше не используются.

Код действует 15 минут, допускает 5 попыток ввода и используется один раз. Повторная отправка разрешена через минуту, максимум 5 писем на email за час. В базе хранится HMAC кода, а после смены пароля прежние сессии становятся недействительными. При ошибке отправки сайт сообщает об ошибке. Войти можно по имени или email; одинаковый email для новых профилей запрещён.

## Данные и проверки

На сервере документы `users`, `reset`, `library` хранятся в таблице PostgreSQL `flashcards_documents`. Локально используются одноимённые JSON-файлы. Пользователь получает только своё рабочее пространство и явно опубликованные материалы. Прежний профиль сохраняется в `legacy_backup_v1` перед преобразованием.

```bash
.venv/bin/python -m unittest discover -s tests -v
node --check assets/app.js
```

Для резервного копирования есть `backup_data.py`: `export`, `check`, `restore-empty`. Нужен отдельный секрет `BACKUP_KEY` в формате Fernet, а для экспорта — `DATABASE_URL`. Для восстановления требуется явно заданный `RESTORE_DATABASE_URL`; непустая база не перезаписывается. Секреты хранить вне Git и отдельно от зашифрованной копии. Реальное восстановление выполнять на отдельной тестовой базе до выпуска.

Для интеграционных тестов задайте `FLASHCARDS_TEST_DATABASE_URL` отдельно: допускается только база с именем `flashcards_qa_*`. Тесты создают и удаляют собственные временные схемы, не меняя восстановленные рабочие документы. Без этой переменной три проверки PostgreSQL пропускаются; остальные тесты выполняются локально.

## Google Sheets

[Настройка Google и выпуск](docs/google-setup.md). Синхронизация выполняется после правок приложения, по кнопке «Обновить» и раз в минуту при открытом приложении вне занятия; закрытое приложение не запускает фоновую синхронизацию. Во время занятия и редактирования формы автоматическое обновление приостановлено.

В новую строку таблицы вводят тему, название набора, вопрос и ответ; источник необязателен. ID и автора заполняет приложение. Названия существующих тем и наборов меняют в приложении. Если в одной теме есть несколько наборов с одинаковым названием, перед массовым добавлением нужно дать им разные названия. Формулы не выполняются при записи из приложения.
