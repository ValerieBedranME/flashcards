# Защита данных и стабильность

Статус: пользователь поручил спроектировать эти правила самостоятельно, заранее согласовал решения и разрешил сразу начинать реализацию. План проверок также согласован. Повторное разрешение на реализацию не требуется.

- Владельца определяет серверная сессия. Проверять права на каждый набор, карточку, таблицу, прогресс и действие; имя или идентификатор из запроса сами по себе доступа не дают. Новые предметы задаются конфигурацией проекта, без пользовательского API их создания.
- Изменяющие запросы защищаются от отправки с чужого сайта. Google подключается через одноразовое состояние OAuth, привязанное к текущему профилю; ключи и токены не возвращаются в браузер и не попадают в Git или логи. Токены Google шифруются на сервере. Запрашивается доступ только к файлам приложения.
- Публикация хранит отдельный неизменяемый снимок. Копия получает новые личные идентификаторы и ссылку на происхождение. Прогресс в публикации и копии не переносится.
- До преобразования старого профиля сохраняется его исходный снимок. Перенос повторяемый: сохраняет идентификаторы старых карточек, оценки, сроки и личные изменения, не создаёт дубликатов. Перед публикацией дополнительно нужна резервная копия производственной базы и проверка восстановления.
- Изменения базы выполняются под межпроцессной транзакционной блокировкой. Для правок используются версии; повторные операции распознаются по ключу действия. Ошибку внешнего сервиса нельзя принять за пустой документ или подтверждённое удаление.
- Содержание подключённого набора берётся из Google Sheets; приложение хранит рабочую копию, последнюю подтверждённую версию и незавершённые действия. Загрузка и запись отделены от сообщения об успехе. Конкурирующая правка сохраняется как отдельный вариант до выбора владельцем.
- Синхронизация не перезаписывает всю таблицу устаревшей копией. Служебные идентификаторы защищены; строки ищутся по идентификаторам, а не по номеру. Повреждённый заголовок, повторный идентификатор или неполное чтение блокируют разрушительную запись. Удаление фиксируется в корзине, восстановление сохраняет личный идентификатор и прогресс.
- Пользовательские тексты выводятся как текст, не исполняются как HTML, JavaScript или формула Google Sheets. Размеры входных данных ограничены; исключения не раскрывают секреты.
- Файлы данных и резервные копии не раздаются веб-сервером. На Vercel используется постоянная база; отсутствие базы или ключей вызывает понятную ошибку, а не небезопасный режим.
- При смене аккаунта очищается состояние предыдущего профиля. Сетевые ошибки не стирают уже загруженные материалы. Интерфейс показывает несохранённые изменения и возможность повторить действие.
- Локальные автоматические проверки, браузерные проверки, реальная интеграция Google и проверка после публикации учитываются отдельно. Непроверенный сценарий не считается успешным. Публикация выполняется после итоговых проверок, согласно согласованному плану.

Основание OAuth: [официальный процесс Google](https://developers.google.com/identity/protocols/oauth2/web-server), [области доступа Sheets](https://developers.google.com/workspace/sheets/api/scopes).

Сетевое ожидание Google освобождает общую блокировку; перед сохранением выполняется объединение со свежими данными. Задание записи сохраняется до внешнего действия. Для создания таблицы отдельно сохраняется короткая аренда, чтобы второй запрос не создал ещё один файл.

Граница текущей реализации: прямая правка той же ячейки в коротком окне между контрольным чтением и записью Sheets пока требует дополнительного протокола. Полная приёмка и выпуск до закрытия этого вопроса не подтверждены; пользователь уже разрешил самостоятельно спроектировать защиту.
