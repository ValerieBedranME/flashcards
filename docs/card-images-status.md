# Изображения и анимация — состояние реализации 14 сентября 2026

Пользователь согласовал макет, весь план реализации, проверки и публикацию после проверок. Повторно спрашивать об этих этапах не требуется. Дополнительные разрешения Google и платные сервисы требуют отдельного конкретного согласования.

## Реализовано в ветке feat/card-images-motion

- Изображения вопроса и ответа, включая сторону только с изображением; прежние ID и SRS сохраняются.
- Закрытые неизменяемые вложения в существующем постоянном хранилище PostgreSQL (отдельные документы); локальные JSON только для разработки.
- Чтение по серверной сессии: собственные загрузки, ссылки своих карточек/корзины/спорных версий либо доступная публикация. Ссылки на чужие неопубликованные картинки отклоняются при изменении карточки.
- Исходные JPEG/PNG/WebP до 2 МБ, до 16 МП; проверка декодером, удаление метаданных, уменьшение до 2400 px, преобразование WebP. Лимит загруженных изображений профиля 100 МБ. Неиспользуемые загрузки пока не очищаются автоматически.
- Копия получает новый ID карточки и ссылки на неизменяемые изображения. Замена ссылки в копии не меняет оригинал или публикацию.
- Загрузка из формы, отдельное увеличение (в том числе поверх редактора без потери формы), показ ответа отдельной кнопкой, полный ID с копированием.
- Цвета оценок и счётчиков, короткие переходы, завершение со ступенями, настройка отключения; системный reduced motion учитывается.
- Текущий текстовый Google-импорт сохраняет существующие изображения карточки.

## Google: проверено и что осталось

Отдельная тестовая таблица в папке ChatGPT:

Вкладка «Проверка», sheetId 1959832783. A1:C2: ID и две картинки. В B2 через интерфейс «Insert an image in the cell» вставлен настоящий PNG. Видимое изображение подтверждено; REST CellData B2 возвращает пустой объект. Не заменять это испытание IMAGE-формулой.

Привязанный Apps Script:
https://script.google.com/u/0/home/projects/17Uyr6BHJRN2YYRicsLerVPKpfmbEwJwvZFSvAiD9ao58JKFQMdwQg43N/edit

Сохранена функция verifyCellImage, эквивалент docs/google-images-probe.gs. Ограничена точным тестовым spreadsheet ID, @OnlyCurrentDoc; считывает B2, скачивает байты с Google, пишет копию в C2, логирует только размер/тип/хеш/факт копии. Ни токены, ни временный URL не логируются.

24 сентября пользователь разрешил запрошенный доступ. При возобновлении Run выполнился без дополнительного окна авторизации. Журнал verifyCellImage: Execution completed; B2, 2394 байта, image/png, SHA256 37c9eb954c0a26dffe20cb6fbceecf246543156e2d370e1210b8b77de36626c7, copied:true. Видимая копия в C2 проверена в Google Sheets.

Затем проверена запись сохранённых байтов через CellImageBuilder.setSourceUrl(data URI). verifyImageBytes успешно создала изображение в C3: copiedFromBytes:true, Execution completed. Картинка в C3 видна (строка стандартной высоты). Общедоступная ссылка для обратного переноса не потребовалась. Этот результат подтверждает транспорт изображения внутри Apps Script, но ещё не интеграцию с Flask.

В онлайн-проекте сейчас сохранена только verifyImageBytes; обе функции сохранены в docs/google-images-probe.gs. Разрешение пользователя относится к тестовой таблице и чтению её тестового изображения с Google. Не трактовать его как согласие на более широкие права или доступ посторонних.

## 24 сентября: чтение настоящих изображений без Apps Script

Обнаружен более простой путь: Google Drive `files.export` возвращает XLSX с настоящими картинками из ячеек. На отдельной тестовой таблице проверены изображения в L2 и M2 (2394 и 2694 байта); экспорт содержит их как привязки к строке 2, код прочитал обе. Это не `IMAGE()`-формулы и не общедоступные ссылки.

В рабочую ветку добавлен импорт изображений из L/M через этот экспорт. Перед привязкой картинки экспортируемые A:K сверяются с прочитанными значениями Google Sheets; при различии обновление прерывается без перестановки картинок между карточками. Google-версия файла позволяет не скачивать XLSX повторно, если он не менялся. Прежние 11 колонок и служебные ID не переписываются; L/M добавляются при первом обновлении предмета. Изображения в приложении остаются приватными, включая независимые копии.

Прямая запись картинки из формы приложения в нативную ячейку Google Sheets через текущий OAuth/Sheets API невозможна. В интерфейсе и README объяснено, что такую картинку можно отдельно вставить в L/M. Экспорт Drive ограничен 10 МБ на весь файл; при превышении сохраняются прежние карточки, пользователь получает ошибку. Для больших таблиц и полного обратного переноса потребуется отдельный протокол Apps Script либо другое согласованное решение. До его реализации нельзя объявлять синхронизацию изображений полностью двусторонней.

Проверки тестовой ветки: 79 unittest, 75 успешно, 4 PostgreSQL-интеграционных пропущены без отдельной QA-базы. Ручная проверка реального XLSX из Google Таблицы подтвердила L2/M2; код импорта и защиты от перестановки строк проверен также синтетическим XLSX. Основная таблица и production не изменялись.
