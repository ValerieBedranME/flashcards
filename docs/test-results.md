# Результаты проверки — 13 сентября 2026

Статус: **локальная реализация, приёмка не завершена, публикации не было**. Ветка `feat/personal-decks-google-sheets`. Работа разрешена пользователем; повторное утверждение плана или защиты не требуется.

## Среды

- Автоматические проверки: 54 локальные проверки проходят. Дополнительно 3 интеграционные проверки пройдены на настоящем PostgreSQL в отдельной базе Neon. Обычный запуск без `FLASHCARDS_TEST_DATABASE_URL` показывает 57 тестов и 3 пропуска; это не 57 выполненных тестов в локальном запуске. Реальные проверки Google описаны ниже отдельно.
- Браузер: настоящий Flask на `127.0.0.1:43129` и `localhost:43129`, разные cookies. Отдельные синтетические профили «Тест Валерия» и «Тест Маша». Для двух правок одного профиля использовались две вкладки `localhost`.
- Рабочий Vercel просмотрен без изменений: Ready, `main`, коммит `19adb64`. Новый код на хостинг не отправлялся.
- В Google Cloud приняты разрешённые пользователем условия и доступ `drive.file`, создан Web OAuth client, включены Sheets/Drive API. Настоящее подключение одного Google-аккаунта выполнено; создана таблица синтетического профиля «Тест Маша». После проверки структурного сбоя создан новый файл восстановления, предыдущий сохранён. Второго Google-аккаунта пока нет; его адрес запрошен у пользователя.
- В Vercel сохранены только несекретные `GOOGLE_CLIENT_ID` и `PUBLIC_BASE_URL` для Production. Секреты подготовлены локально; передача Vercel ещё не разрешалась отдельно и не выполнялась. Переразвёртывания не было. Переменные БД и почты относятся только к Production, Preview к рабочей БД не подключён.
- Создана зашифрованная копия рабочей базы; восстановлена в отдельную пустую `flashcards_qa_20260913`. Сверено полное содержимое двух документов, проверен перенос двух существующих профилей. Тесты PostgreSQL используют отдельные временные схемы этой тестовой базы, рабочие документы не менялись.

## Дополнительные проверки защиты

OAuth привязан к профилю, использует одноразовый state и PKCE; повтор callback не получает доступ. Тесты подтверждают шифрование токенов и отсутствие секретов в bootstrap. Старые изменяющие API не позволяют обойти проверки версий для подключённой таблицы. Выбор спорной правки содержит отпечаток увиденных вариантов; новая правка требует заново посмотреть варианты.

Новые импортированные строки не попадают в занятие до подтверждения ID в таблице. Повтор импорта после изменения строки не оставляет лишнюю карточку. Добавление позже ещё одной строки с таким же текстом создаёт новую карточку; одинаковый текст не считается идентификатором. Взятую копию можно дополнить строками в Sheets с сохранением исходного автора; неоднозначные названия наборов вызывают явную ошибку.

## Что осталось до выпуска

1. Пройти оставшиеся реальные сценарии с таблицами второго Google-аккаунта и обмен в обе стороны. Разрешение на доступ первого аккаунта уже получено; его не запрашивать заново.
2. С разрешением передать подготовленные `GOOGLE_CLIENT_SECRET` и `GOOGLE_TOKEN_KEY` в защищённые переменные Production Vercel. Стабильный ключ сессий и рабочее подключение БД сохранить. Локальные страницы о данных и правилах готовы; для Google Branding нужны действующие ссылки после публикации.
3. Завершить внешние настройки Google для одногруппников, оставшиеся сценарии; затем выпуск и T24. Перед выпуском сделать свежий backup, если рабочие данные изменились. Не считать подготовку параметров состоявшейся публикацией.

Подробности настройки: [Google и выпуск](google-setup.md). Непроверенные части не считаются пройденными.

Дополнительно проверены короткая аренда создания таблицы (повторный запрос не создаёт второй файл), сохранение ID после ошибки настройки и повторное использование этого файла.

Последний браузерный повтор: конфликт автоматически открывает два варианта, выбор проверяется по отпечатку версии и сохраняется; ошибок console нет. В светлой теме у получателя сохранено «Не уверен: 1», у автора осталось «Знаю: 1». Тестовая смена color-scheme сделана только в локальном скрипте предпросмотра, настройки пользователя не изменялись.

Проверки 13 сентября: 54 локальных теста прошли; 3 отдельных теста PostgreSQL прошли за 50,8 с. Добавлен тест понятной подсказки при отозванном refresh token. Сохранение состояния повтора при 503 и откат неожиданного 500 подтверждены настоящими транзакциями. Ключ резервной копии хранится отдельно от зашифрованного файла, вне Git.

При интенсивном реальном прогоне один запрос получил временный отказ Google; незавершённое задание сохранилось. Продолженный прогон прошёл с ограничением частоты тестовых запросов. Отдельный вспомогательный сценарий восстановления был исправлен: API требует актуальную revision карточки и справедливо отклонил тестовый запрос без неё. Эти остановки не считались успешными проверками; исправленные сценарии повторены.
