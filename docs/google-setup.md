## Протокол синхронизации и ограничения

- Google разрешает приложению доступ к созданным им файлам через `drive.file`. Маркер `appProperties` помогает найти уже созданную таблицу после потерянного ответа. Сервисные запросы не получают доступ ко всему Диску.
- Перед записью в Google в базе сохраняются импортированные ID и задание записи. Следующий запрос выполняет запись, перечитывает таблицу и подтверждает результат. Повтор после потерянного ответа узнаёт уже записанные строки. Новые импортированные карточки становятся доступны для занятия после подтверждения ID в таблице.
- Для правок используется последняя общая версия, текущая рабочая копия и прочитанное содержимое таблицы. Конфликт хранит оба варианта; выбор привязан к той версии, которую видел пользователь.
- Перед записью таблица перечитывается; при изменении готовится новое слияние. Записываются только изменившиеся ячейки, затем результат перечитывается. Поддерживается до 9999 строк за обновление и до 12 МБ ответа Google; превышение вызывает ошибку без очистки данных.
- Запись карточек переведена на один `spreadsheets.batchUpdate`: сначала `duplicateSheet` сохраняет точный снимок перед записью, затем `updateCells` изменяет ячейки, затем второй `duplicateSheet` фиксирует результат. Google документирует последовательность и атомарное применение запросов такого пакета. Снимки скрыты, привязаны к ID задания и проверяются после записи и при повторе. Предыдущая подтверждённая пара удаляется лишь вместе с созданием следующей. Текст записывается как `stringValue`, без выполнения формул.
- Если точный снимок отличается от контрольного чтения, правка одной ячейки сохраняется отдельным вариантом в профиле. Перемещение или вставка строк в этот момент приостанавливает синхронизацию и сохраняет оба полных снимка. Кнопка «Восстановить таблицу» готовит новую личную таблицу из сохранённых данных; прежний файл остаётся доступен в «Предыдущих таблицах». Одинаковые ID и SRS сохраняются, конфликтующие тексты предлагаются для выбора. Повтор восстановления не создаёт новое задание.
- Новый протокол проверен на настоящей Google-таблице: правка **после последнего чтения** сохранена отдельным вариантом, потеря ответа после фактической записи и последующая правка не вызывают повторной перезаписи. Перемещение строк во время фактического атомарного пакета запускает восстановление. Через браузер создан новый файл, выбран сохранённый текст из старой таблицы; сверены 21 карточка, исходное авторство, прежние ID и SRS. Это проверка одного Google-подключения, не двух владельцев.
- Реальный отзыв OAuth проверен отдельно для текущего доступа и обновления токена. Ошибка `invalid_grant` предлагает переподключение. После повторного разрешения прежняя таблица доступна и успешно обновляется; лишний файл не создаётся.
- Внешние запросы Google освобождают общую блокировку. Перед сохранением результат объединяется со свежим состоянием личного профиля; несовместимая правка отменяет устаревшую запись и предлагает повторить обновление. Создание таблицы защищено отдельной короткой арендой для владельца. Проверено отдельным потоком на настоящем PostgreSQL в тестовой базе. Запуск фоновых серверных заданий здесь не реализован.

Официальные источники: [OAuth web-server](https://developers.google.com/identity/protocols/oauth2/web-server), [области доступа Sheets](https://developers.google.com/workspace/sheets/api/scopes), [частные свойства файлов Drive](https://developers.google.com/workspace/drive/api/guides/properties), [атомарный пакет обновлений](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/batchUpdate).
