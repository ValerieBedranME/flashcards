# Подключение Google и подготовка выпуска

## Что подготовлено

В Google Cloud создан отдельный проект **FlashCards**, ID `acquired-script-508417-i7`. Существующий проект `2026` и его Desktop client не изменялись.

В форме Google Auth Platform заполнены название FlashCards, внешний тип доступа и контакт владельца. Финальный шаг требует принятия Google API Services User Data Policy. Этот шаг оставлен открытым; пользователю задан отдельный вопрос согласно правилам управления браузером. Условия ещё не приняты, OAuth-клиент пока не создан, Google API в новом проекте ещё не включены.

## Оставшиеся настройки

1. Принять условия после ответа пользователя, закончить оформление Google Auth Platform.
2. Включить Google Sheets API и Google Drive API в новом проекте.
3. Создать OAuth-клиент типа Web application. Redirect URI рабочего приложения: `https://flashcards-wheat-alpha.vercel.app/api/v2/google/callback`. Для локальной интеграционной проверки отдельно добавить `http://localhost:43129/api/v2/google/callback`.
4. На тестовом этапе добавить Google-аккаунты участников проверки в Test users. До запуска для одногруппников настроить внешний production-доступ Google; не путать список Google Test users с регистрацией FlashCards по обычной ссылке.
5. На сервере задать `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, постоянный `SECRET_KEY`, отдельный `GOOGLE_TOKEN_KEY` в формате Fernet и `PUBLIC_BASE_URL`. Для рабочего приложения последний равен `https://flashcards-wheat-alpha.vercel.app`. Секреты не помещать в Git или сообщения.
6. Проверить реальный вход Google, создание личных таблиц, 20 строк, авторство копии, правки в обе стороны, удаление, переподключение и два отдельных профиля. Существующая таблица-шаблон не является доказательством работающей интеграции.
7. Сделать зашифрованную копию рабочей PostgreSQL-базы и пробное восстановление в пустую тестовую базу; выполнить проверку переноса. Preview должен использовать отдельную базу, чтобы тестовый вход не преобразовал рабочие профили.
8. После закрытия приёмки опубликовать из `main` и отдельно пройти T24 на фактическом домене. Сейчас рабочий Vercel проверен визуально: версия `19adb64`, статус Ready. Новая ветка туда не отправлялась.

## Протокол синхронизации и ограничения

- Google разрешает приложению доступ к созданным им файлам через `drive.file`. Маркер `appProperties` помогает найти уже созданную таблицу после потерянного ответа. Сервисные запросы не получают доступ ко всему Диску.
- Перед записью в Google в базе сохраняются импортированные ID и задание записи. Следующий запрос выполняет запись, перечитывает таблицу и подтверждает результат. Повтор после потерянного ответа узнаёт уже записанные строки. Новые импортированные карточки становятся доступны для занятия после подтверждения ID в таблице.
- Для правок используется последняя общая версия, текущая рабочая копия и прочитанное содержимое таблицы. Конфликт хранит оба варианта; выбор привязан к той версии, которую видел пользователь.
- Перед записью таблица перечитывается; при изменении готовится новое слияние. Записываются только изменившиеся ячейки, затем результат перечитывается. Поддерживается до 9999 строк за обновление и до 12 МБ ответа Google; превышение вызывает ошибку без очистки данных.
- У Google Sheets Values API нет используемой здесь атомарной проверки версии отдельной ячейки. Между последним чтением и записью остаётся короткое окно для прямой правки **той же ячейки** человеком. Тесты трёхстороннего слияния не доказывают устранение этого окна. Это ограничение нужно закрыть отдельным протоколом журнала правок/раздельных полей и проверить до выпуска; нельзя обещать абсолютную защиту на основании текущих тестов.
- Внешние запросы Google освобождают общую блокировку. Перед сохранением результат объединяется со свежим состоянием личного профиля; несовместимая правка отменяет устаревшую запись и предлагает повторить обновление. Создание таблицы защищено отдельной короткой арендой для владельца. Это проверено локальным параллельным тестом; нагрузка на настоящем PostgreSQL ещё должна быть проверена. Запуск фоновых серверных заданий здесь не реализован.

Официальные источники: [OAuth web-server](https://developers.google.com/identity/protocols/oauth2/web-server), [области доступа Sheets](https://developers.google.com/workspace/sheets/api/scopes), [частные свойства файлов Drive](https://developers.google.com/workspace/drive/api/guides/properties), [запись значений](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/batchUpdate).
