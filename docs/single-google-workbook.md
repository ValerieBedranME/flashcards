# Одна личная таблица с вкладками

Согласовано пользователем: один Google-файл на личный профиль, вкладки «Анатомия», «Латынь», «Микробиология». Правило «одна тема — один набор» сохраняется.

В профиле одна ссылка «Открыть таблицу» и кнопка «Обновить всё». Для прежних подключений — «Объединить в одну таблицу», для новых — «Создать мою таблицу». После перехода прежние файлы доступны в резервном разделе и больше не синхронизируются. Добавлять новые карточки нужно в новый файл.

## Перенос и повтор

- Обновить прежние таблицы, завершив сохранённые задания синхронизации. Структурные конфликты требуют прежнего восстановления.
- Резервирование создания в базе перед сетью. Один файл с маркером Drive на владельца и поколение восстановления.
- Отдельный запрос на каждую вкладку. Единый атомарный пакет создаёт вкладку со стабильным ID, содержимым и оформлением. Повтор после потерянного ответа узнаёт вкладку и не переписывает последующие правки.
- Все ссылки переключаются одной транзакцией после подготовки трёх вкладок. При сбое можно продолжить из профиля. Исходные файлы и данные остаются доступны.
- Переносятся строки и прежняя общая версия для обычного трёхстороннего слияния. Существующие ID карточек, авторство и SRS не меняются. Новые строки разных предметов получают разные ID даже при одинаковом тексте.
- Копия каждого исходного листа отражает его содержимое в момент чтения при переносе. Правки старого файла после этого момента остаются в резервном файле; после перехода редактировать нужно новую таблицу.
- Обновление предмета и перенос используют согласованные краткие блокировки владельца. Сеть освобождает общую транзакцию; сохранение объединяется с актуальным состоянием.
- Протокол before/after-снимков работает отдельно для каждой вкладки. Восстановление повреждённой структуры создаёт новое поколение общей таблицы, сохраняя прежнюю.

## Проверено до выпуска

13 сентября: 63 локальных теста прошли, 4 PostgreSQL-теста пропущены без отдельного подключения. Новые проверки: один файл/три вкладки, разные владельцы, одинаковые строки разных предметов, перенос несинхронизированной правки с сохранением автора и SRS, потеря ответа и повтор без перезаписи, блокировка переноса при незавершённой записи. Остальные проверки протокола синхронизации пройдены в общей серии.

В браузере на изолированной версии с имитацией Google проверены создание общей таблицы и состояние профиля с одной ссылкой и тремя результатами обновления. JavaScript проверен командой node --check. Реальная таблица проверяется отдельно после публикации; локальная имитация не считается проверкой Google.
